# Notes
#
# family-blue
#   #4B83CD was the original blue, but it only reached 3.71:1 against the
#   off-white background. It was darkened to #406FAE (4.90:1) to satisfy the
#   contrast core rule, keeping the same hue.
#   Used for: keywords, HTML tags, links, terminal blue/cyan.
#
# family-green / family-brown-orange / family-grey
#   Also darkened from their originals (#448C27, #AB6526, #777777) for the
#   same reason. General use: green = added/success, brown-orange =
#   warning/untracked, grey = de-emphasis.
#
# Colorblindness
#   Checked under deuteranopia, protanopia and tritanopia. The red (#AA3731)
#   and the brown-orange (#9F5E23) collapse to nearly the same yellow for
#   red-green deficiencies. Separating them by hue is not possible here: on a
#   near-white background, both are pinned into a narrow contrast band, and
#   pushing them apart drops one below 4.5:1.
#   Per the accessibility core rule, meaning is therefore carried by a second
#   cue rather than by hue alone:
#     - status bar error/warning/remote render with their own icon and label
#     - git gutter decorations use distinct letter glyphs
#     - the diff editor pairs each side with its own border
#   If a future theme has more room, prefer separating red from amber by
#   lightness.
#
# Inherited from the base syntax palette
#   These predate the other-colors.txt entries; they were not chosen to
#   satisfy a core rule, but they are reused for UI states, so a new theme
#   will need them too.
#
#   family-red: #AA3731   errors, git deleted, function names
#   family-deep-red: #660000   illegal code, git conflicts
#   family-purple: #7A3E9D   types, variables, constants
#   diff-grey: #434343   diff ranges and headers
#   markup-black: #000000   markup changed/inserted/deleted
